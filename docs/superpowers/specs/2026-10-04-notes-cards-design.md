# Карточки из конспектов

Дата: 2026-10-04

## Зачем
Конспекты в Obsidian без регулярного повторения забываются, а перечитывание работает хуже самопроверки. Приложение делает из конспектов человека карточки вопрос-ответ, показывает чаще те, что он не знает, и ведет статистику. ИИ работает на ключе самого человека, бесплатно через Gemini.

## Решения
1. Монорепозиторий npm workspaces: `apps/web` (React, TS, Vite, Tailwind, shadcn/ui), `apps/api` (NestJS, Prisma), `packages/core` (парсер, алгоритм, типы без фреймворков). Ядро тестируется отдельно и общее для фронта и бэка. Архитектура по `/devkit:arch`: web `react-evolution` small, api `nest-standard`.
2. UI web: Vite, shadcn/ui на Radix, Drawer на vaul для шторки, `motion` для свайпа и переворота, `react-markdown` с `remark-gfm` без сырого HTML, Shiki с ленивой загрузкой, `lucide-react`, Sonner, TanStack Query, React Router, `idb-keyval`. Готовые компоненты и безопасный Markdown без своей физики жестов.
3. Деплой на свой VPS одним docker compose: nginx раздает собранный web и проксирует `/api` на Nest, Postgres с volume, ежедневный `pg_dump` в папку бэкапов. HTTPS через Let's Encrypt, certbot продлевает сертификат. Один домен для web и api.
4. Вход через GitHub OAuth, только профиль. JWT в httpOnly cookie (`Secure`, `SameSite=Lax`), web и api на одном домене.
5. Источник выбирает человек: публичный репозиторий GitHub по ссылке (ветка и папка опционально) или локальная папка. Для папки File System Access API, в Safari и Firefox `<input webkitdirectory>`.
6. Карточки парсятся в браузере из `> [!question]- вопрос` с ответом в строках `>`. Так оба источника идут одним кодом.
7. Конспекты без таких блоков: Gemini генерирует 3-7 вопросов один раз на хэш текста заметки, карточки хранятся на сервере со значком «ИИ». Генерация растягивается на несколько запусков, чтобы не упереться в бесплатный лимит.
8. `id` карточки = хэш пути заметки и текста вопроса. Правка вопроса создает новую карточку с нуля, зато id не нужно хранить в Markdown.
9. Лейтнер 1-3-7-21-60 дней, после 60 интервал удваивается. «Знал» поднимает на ступень, «не знал» сбрасывает на 1 и возвращает карточку в конец текущей сессии. Это график из «Как писать конспекты».
10. Сессия: просроченные карточки по доле ошибок и сроку просрочки, затем новые до лимита в день (10). Максимум 20 карточек. В статистику идет только первый ответ на карточку в сессии.
11. Сервер хранит пользователя, источник, состояние карточек, журнал ответов, ИИ-карточки и ключ ИИ, зашифрованный AES-GCM. Тексты конспектов не хранит.
12. ИИ: свой ключ Gemini (бесплатно) или OpenAI, модель на выбор. Запросы идут через api, ключ в браузер не попадает. Кнопка «Открыть в ChatGPT» (`chatgpt.com/?q=`) есть всегда и использует подписку человека.
13. Карточка: вопрос на лицевой стороне, на обороте Markdown с подсветкой кода. Свайп вправо значит «знал», влево «не знал», то же делают стрелки, переворот по пробелу.
14. Ответ ИИ и конспект открываются в нижней шторке поверх карточки. В шторке можно задать уточняющий вопрос.
15. Главный экран: число карточек на сегодня и кнопка старта, итоги за все время, серия дней, график активности как в GitHub, проблемные карточки, распределение по ступеням.
16. Итоги сессии: знал и не знал, список ошибок со ссылкой на конспект, советы ИИ (без ключа промпт в ChatGPT), кнопка «Повторить ошибки».
17. Первый запуск в 3 шага: вход, источник, ИИ (можно пропустить). Дальше все это в настройках, плюс экспорт JSON и удаление аккаунта.
18. Фон: переливающийся градиент, темная тема. Анимация отключается в настройках и при `prefers-reduced-motion`.
19. Выкатка: на push в main GitHub Actions гоняет `npm run check`, собирает образы web и api в GHCR и по SSH делает `docker compose pull && up -d`. Сервер ничего не собирает.
20. Офлайн: карточки кэшируются в IndexedDB, ответы копятся в очереди в localStorage до синхронизации, повторная отправка идемпотентна. Сломанная заметка пропускается и попадает в список ошибок разбора.

## Отклонено
1. GitHub Models. Закрыт 30.07.2026, эндпоинт отвечает `OK` вместо ответа модели.
2. Доступ к подписке ChatGPT или Copilot через неофициальные API. Нарушает условия сервисов, аккаунты блокируют.
3. Общий ключ ИИ владельца приложения. Лимиты делятся на всех, плюс злоупотребления и чужой текст от имени владельца.
4. Прогресс в Gist или только в localStorage. Выбрана своя база.
5. Вход в Gemini через Google OAuth. Требует проверку приложения Google на недели.
6. FSRS и взвешенный случайный выбор. Лейтнер совпадает с графиком из конспектов и проще.
7. Парсинг на сервере. Не работает с локальной папкой.
8. Токен в localStorage. Доступен любому XSS.
9. Render и Neon. Свой VPS дает один домен без rewrite, сервер не засыпает, база рядом с api.
10. Сборка образов на сервере. Дешевому VPS может не хватить памяти.
11. Webpack. Нужен для Module Federation и легаси-плагинов, у нас их нет.

## Не делаем
1. GitLab и другие хостинги, приватные репозитории, несколько источников одновременно.
2. PWA, редактирование карточек в приложении, светлая тема.

## Как проверим
1. `npm test -w packages/core`: парсер на заметках формата `notes` (код в ответе, пустой ответ, вложенные callout'ы) и переходы Лейтнера проходят.
2. `npm test -w apps/api`: OAuth, идемпотентная синхронизация, шифрование ключа, прокси ИИ с моком проходят.
3. `npx playwright test`: вход, источник `gribacode/notes`, сессия со свайпами, итоги проходят.
4. `docker compose -f deploy/compose.yml up` локально поднимает nginx, api и Postgres, страница открывается, `/api/health` отвечает.
5. На VPS после push в main: сайт открывается по HTTPS, cookie с флагом HttpOnly, при отключенной сети сессия идет, после возврата ответы появляются в статистике.
6. `npm run lint:arch -w apps/web` и `-w apps/api` проходят.
